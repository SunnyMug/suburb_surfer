# Suburb Surfer

Explore suburbs across Australian capital cities. Pick a random suburb or search by name, then browse an overview, food scene, and local history on an interactive map.

Live at [suburb-surfer.vercel.app](https://suburb-surfer.vercel.app)

---

## Tech Stack

- Next.js (App Router), TypeScript, Tailwind CSS
- MapLibre GL JS — GPU-accelerated vector map with Carto basemaps & custom boundary polygons
- Recharts for interactive demographic visualisations
- Groq Cloud — LLaMA 3.3 70B with LLaMA 3.1 8B as fallback
- Wikipedia MediaWiki Action API
- OpenStreetMap (Nominatim + Overpass)
- Upstash Redis for rate limiting (optional)

---

## How it works

When you search for or randomly pick a suburb, the app coordinates multiple parallel data sources:

- **Wikipedia** — the History, Demographics, Heritage listings, Notable residents, and Name/Etymology sections from the suburb's Wikipedia article
- **OpenStreetMap (Overpass & Nominatim)** — verified dining venues, official suburb polygon boundaries, and public transport infrastructure:
  - Nearby train stations (`railway=station`), light rail/tram stops (`railway=tram_stop`), ferry wharves (`amenity=ferry_terminal`), and bus stops (`highway=bus_stop`)
  - Linear track and corridor geometries (`way["railway"]`, `way["busway"]`) for interactive vector map visualisation
- **Connectivity Snapshot** — synthesises transit connectivity into an intuitive summary (e.g. _"Served by 2 train stations and 4 bus routes"_) with interactive toggles for rail and bus lines on the vector map

Each Wikipedia section is passed to the LLM as a labelled reference block tied to a specific output field — history events come from the History section, heritage sites from Heritage listings, and so on. Restaurant recommendations are strictly restricted to venues confirmed in OSM data. The LLM can only fall back to its own knowledge when a section is missing, and is instructed to flag uncertainty when it does.

## Running locally

1. Clone and install:

```bash
npm install
```

2. Create `.env.local`:

```
GROQ_API_KEY=your_key_here

# Optional — Supabase persistent global cache (instant ~50ms loads worldwide)
NEXT_PUBLIC_SUPABASE_URL=https://your-project-id.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=eyJhbGciOi...

# Optional — enables per-IP rate limiting
UPSTASH_REDIS_REST_URL=your_url_here
UPSTASH_REDIS_REST_TOKEN=your_token_here
```

Free Groq API keys are available at [console.groq.com/keys](https://console.groq.com/keys).

If using Supabase for caching, run this SQL in your Supabase SQL Editor:

```sql
create table if not exists public.suburb_cache (
  id bigint generated by default as identity primary key,
  city text not null,
  suburb text not null,
  data jsonb not null,
  updated_at timestamp with time zone default timezone('utc'::text, now()) not null,
  unique(city, suburb)
);

create index if not exists idx_suburb_cache_lookup on public.suburb_cache (lower(city), lower(suburb));

alter table public.suburb_cache enable row level security;
create policy "Allow public read access" on public.suburb_cache for select using (true);
create policy "Allow public insert" on public.suburb_cache for insert with check (true);
create policy "Allow public update" on public.suburb_cache for update using (true);
```

3. Start the dev server:

```bash
npm run dev
```

## Disclaimer

Content is generated by a large language model grounded where possible by Wikipedia and OpenStreetMap data. It can still be incorrect or outdated. Restaurant recommendations should be verified before visiting.
